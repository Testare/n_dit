# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Run Commands

```bash
cargo build                  # Build (default member: n_dit binary)
cargo run                    # Run the game
cargo run -- --debug         # Run with debug logging + Bevy Remote Protocol
cargo run -- --trace         # Trace-level logging
cargo run -- --uncapped      # No frame cap
cargo run -- --rainbow 10    # Demo shader (sliding rainbow effect)
cargo run -- -f save.json    # Specify save file
cargo test                   # Run all workspace tests
cargo clippy                 # Lint
cargo fmt                    # Format (uses unstable features, requires nightly)
cargo hakari generate        # Regenerate workspace-hack after dependency changes
nix flake check              # Full CI: clippy, fmt, tests, audit, hakari verify
```

## Architecture

n_dit is a TUI recreation of "The Nightfall Incident" (Lego Spybotics flash game) built on **Bevy 0.16 ECS** (custom fork: `bevy-0.16-bookmark` branch).

### Crate Structure

- **`n_dit`** — Binary entry point. CLI parsing (clap), plugin wiring, logging setup.
- **`game_core`** — All game logic: board, cards/curios, nodes, entity grid, player, dialog, saving, operations. No rendering code.
- **`cq_term`** — Terminal UI renderer: crossterm I/O, taffy layout, input handling, board/node/dialog UI, animations. Depends on game_core and charmi.
- **`charmi` / `charmi_core` / `charmi_macro`** — "Character Map Image" library for terminal graphics. Custom TOML-based image format with proc macro DSL. charmi_macro uses edition 2024.
- **`workspace-hack`** — Auto-generated by cargo-hakari for build optimization.

### System Pipeline

Game logic runs through ordered Bevy system sets defined in `NDitCoreSet`:

`RawInputs` (First) → `ProcessInputs` (PreUpdate) → `ProcessCommands` → `ProcessCommandsFlush` → `PostProcessCommands` → `ProcessUiOps` → `PostProcessUiOps` (Update)

### Key Design Principles

- **UI/logic separation**: `game_core` has zero rendering dependencies. All display goes through `cq_term`. This enables future GUI or CLI frontends.
- **Multiplayer-ready**: Code assumes eventual multiplayer support.
- **Terminology**: Game pieces are called "Curios" (not "Programs" as in the original game).

## Key Dependencies

- **Bevy 0.16** — patched fork at `github.com/Testare/bevy.git` branch `bevy-0.16-bookmark`
- **crossterm** — Terminal I/O and events
- **taffy** — UI layout engine
- **bevy_yarnspinner** — Dialog/narrative system
- **charmi** — In-workspace character map image rendering
